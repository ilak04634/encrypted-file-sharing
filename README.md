# Encrypted File Sharing

Учебный проект для передачи файлов по локальной сети со сквозным
шифрованием.

Проект разрабатывается на Python командой из четырёх человек.
Диффи — Хеллман и AES реализуются вручную.

## Принцип работы

1. Два клиента подключаются к серверу.
2. Клиенты обмениваются открытыми значениями Диффи — Хеллмана через сервер.
3. Каждый клиент самостоятельно получает общий секрет и ключ шифрования.
4. Отправитель выбирает файлы.
5. Клиент отправителя шифрует файлы алгоритмом AES.
6. Сервер пересылает зашифрованные данные получателю.
7. Получатель выбирает место сохранения.
8. Клиент получателя расшифровывает и сохраняет файлы.

Сервер выполняет роль ретранслятора. Закрытые значения
Диффи — Хеллмана и ключи шифрования ему не передаются.

## Назначение файлов

### main_client.py — запуск клиента

Точка входа в клиентское приложение.

Создаёт и запускает приложение из client/application.py.

Здесь не должно быть реализации интерфейса, шифрования или
сетевого протокола. Файл нужен только для запуска клиента.

### main_server.py — запуск сервера

Точка входа в серверное приложение.

Создаёт и запускает сервер из server/relay.py.

Основная логика ретрансляции находится в relay.py.

### client/__init__.py — пакет клиента

Обозначает каталог client как Python-пакет.

На первом этапе может оставаться пустым.

### client/application.py — объединение компонентов

Управляет общим сценарием работы клиента и связывает GUI,
сеть и криптографию.

Отвечает за последовательность действий:

- подключение к серверу;
- организацию обмена ключами;
- запуск шифрования;
- передачу зашифрованных файлов;
- обработку входящих файлов;
- запуск расшифрования и сохранения;
- передачу состояния и ошибок в GUI.

Вызывает готовые функции других модулей.
Не содержит реализацию AES или Диффи — Хеллмана.

### client/network.py — сетевой клиент

Отвечает за соединение с сервером и обмен данными через сокеты.

Основные задачи:

- подключение и отключение;
- отправка сообщений;
- получение сообщений и частей файлов;
- обработка сетевых ошибок;
- передача полученных данных в application.py.

Для упаковки и чтения сообщений использует protocol.py.

Не шифрует файлы и не обращается напрямую к элементам GUI.

### client/gui.py — графический интерфейс

Содержит окно приложения и обработчики действий пользователя.

Предоставляет возможность:

- указать адрес сервера и получателя;
- подключиться к серверу;
- выбрать файлы для отправки;
- принять или отклонить входящий файл;
- выбрать место сохранения;
- увидеть состояние операции и ошибки.

Передаёт действия пользователя в application.py.
Не содержит реализации шифрования и сетевого обмена.

### server/__init__.py — пакет сервера

Обозначает каталог server как Python-пакет.

На первом этапе может оставаться пустым.

### server/relay.py — сервер-ретранслятор

Принимает подключения клиентов и пересылает сообщения между ними.

Основные задачи:

- хранить соответствие идентификаторов клиентов их соединениям;
- определять адресата сообщения;
- пересылать сообщения и зашифрованные данные;
- обрабатывать отключения и недоступность получателя.

Для чтения и отправки сообщений использует protocol.py.

Не вычисляет общий секрет, не получает секретные ключи,
не расшифровывает и не сохраняет передаваемые файлы на диск.

### crypto/__init__.py — пакет криптографии

Обозначает каталог crypto как Python-пакет.

На первом этапе может оставаться пустым.

### crypto/diffie_hellman.py — согласование ключей

Содержит ручную реализацию обмена Диффи — Хеллмана.

Основные задачи:

- создание закрытого и открытого значений;
- проверка открытого значения собеседника;
- вычисление общего секрета;
- получение из общего секрета ключа согласованной длины.

Преобразование общего секрета в ключ должно выполняться
одинаковым, заранее согласованным способом на обоих клиентах.

Модуль работает с числами и байтами.
Не использует сеть, файлы или GUI.

### crypto/aes.py — шифрование и расшифрование

Содержит ручную реализацию AES и функции обработки файлов.

Основные задачи:

- проверка длины ключа;
- реализация преобразований AES;
- обработка блоков в согласованном режиме;
- шифрование файла;
- расшифрование файла.

Получает пути и ключи через аргументы функций.
Не открывает диалоги выбора файлов и не отправляет данные по сети.

### protocol.py — общий формат сетевых сообщений

Содержит правила обмена данными, общие для клиента и сервера.

Определяет:

- типы сообщений;
- обязательные поля;
- способ передачи заголовка и бинарных данных;
- функции упаковки, отправки и чтения сообщений;
- ограничения размеров и проверку формата.

Например, позволяет отличить открытое значение DH
от части файла или подтверждения получения.

Не управляет подключением клиентов и не выполняет шифрование.

### README.md — руководство для команды

Описывает назначение проекта, структуру, распределение работы
и общие договорённости.

Обновляется при изменении архитектуры и способов запуска.

## Распределение работы

| Участник | Основная ответственность |
|---|---|
| Участник 1 | crypto/diffie_hellman.py |
| Участник 2 | crypto/aes.py |
| Илья | client/network.py, server/relay.py, protocol.py |
| Участник 4 | client/gui.py |
| Илья и участник 4 | client/application.py и объединение компонентов |

Распределение не запрещает помогать друг другу.
Изменения в чужой части предварительно обсуждаются.

## Правила написания кода

1. Используем одну согласованную версию Python.
2. Сторонние библиотеки добавляем только после обсуждения.
3. Для публичных функций указываем типы аргументов и результата.
4. Кратко описываем назначение публичных функций и возможные ошибки.
5. Бинарные данные и ключи передаём как bytes, пути — как pathlib.Path.
6. Не преобразуем содержимое файлов в текст.
7. В криптографических модулях не используем input(), GUI и сокеты.
8. Ошибки передаём исключениями, не скрываем через except: pass.
9. Не записываем секретные ключи в логи и репозиторий.
10. При импорте модуля не запускаем окна и сетевые подключения.
11. Длительные операции выполняем вне главного потока GUI.
12. Перед изменением общего интерфейса предупреждаем тех,
    кто его использует.
13. Каждый проверяет свою часть отдельно до объединения проекта.

Классы используем для объектов с состоянием:
обмена DH, соединения, приложения.
Для независимых операций достаточно функций.

## Что согласовать до объединения

- Названия, аргументы и результаты общих функций.
- Параметры Диффи — Хеллмана и способ получения ключа из общего секрета.
- Длину ключа AES, режим работы и обработку последнего блока.
- Способ проверки целостности и подлинности переданных данных.
- Формат сообщений и идентификаторов клиентов.
- Передачу событий между сетью, приложением и GUI.
- Поведение при обрыве соединения и совпадении имён файлов.

Начальный вариант: выбранные файлы передаются последовательно.

## Порядок проверки

1. Проверить обмен DH без сети: обе стороны получают одинаковый секрет.
2. Проверить AES по известным тестовым примерам.
3. Проверить шифрование и расшифрование файлов.
4. Проверить передачу тестовых данных через сервер.
5. Объединить передачу и шифрование.
6. Подключить GUI.
7. Проверить полный сценарий на двух клиентах и сервере.

Реальные файлы принимаем во временное расположение.
Окончательное сохранение выполняем после успешной проверки
и расшифрования. Существующие файлы не перезаписываем молча.

## Запуск

Предполагаемые команды из корня проекта:

```bash
python main_server.py
```

Затем на каждом клиенте:

```bash
python main_client.py
```

Аргументы запуска и настройку адреса сервера документируем
после реализации.

## Ограничения

Сам по себе обмен Диффи — Хеллмана не подтверждает личность
собеседника. Защита от активной подмены обмена требует
дополнительного механизма проверки.

Реализации криптографии в проекте являются учебными.
